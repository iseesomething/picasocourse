# 3D-Практикум

Статический образовательный сайт об очных курсах по 3D-печати и обслуживанию принтеров PICASO серии Designer.

Проект не требует сборки, пакетного менеджера и фреймворков. Вся вёрстка, стили, навигация и данные находятся в одном файле `index.html`. Сайт можно открыть напрямую через `file://` или опубликовать на GitHub Pages в корне репозитория или в подпапке.

## Файлы

```text
.
├── index.html             # весь сайт: HTML, CSS, JS, конфиг и данные
├── README.md              # инструкция
├── .nojekyll              # отключает обработку Jekyll на GitHub Pages
└── assets/
    └── printers/
        ├── designer-xl.webp
        ├── designer-x.webp
        └── designer-xl-s2.jpg
```

## Локальный запуск

Самый простой способ — открыть `index.html` в браузере двойным кликом.

Если нужен локальный HTTP-сервер:

```bash
python -m http.server 8000
```

Затем открыть <http://localhost:8000/>.

На Windows при необходимости используйте `py -m http.server 8000`. Node.js и npm не нужны.

> `localStorage` надёжнее всего работает через `http://localhost`. В некоторых браузерах при открытии через `file://` сохранение прогресса может быть ограничено — сайт при этом продолжает работать, но прогресс не сохранится между перезагрузками.

## Маршруты

Навигация построена только на hash-роутинге. History API не используется.

| Адрес | Экран |
| --- | --- |
| `#/` | Главная |
| `#/about` | О компании |
| `#/printer/<id>` | Страница принтера |
| `#/printer/<id>/program/<programId>` | Программа обучения |
| `#/printer/<id>/program/<programId>/lesson/<n>` | Лекция |

Пример прямой ссылки:

```text
#/printer/designer-xl-s2/program/three-day/lesson/2
```

Такой адрес можно открыть сразу после загрузки страницы.

## Прогресс обучения

Для каждой пары «принтер + программа» используется отдельный ключ:

```text
picaso-progress-<printerId>-<programId>
```

Пример:

```text
picaso-progress-designer-xl-s2-three-day
```

В ключе хранится JSON-массив номеров пройденных лекций, например `[1, 3]`. Прогресс не смешивается между принтерами и программами.

Сбросить прогресс можно в DevTools → Application → Local Storage, удалив нужный ключ, или выполнив в консоли:

```js
localStorage.removeItem("picaso-progress-designer-xl-s2-three-day");
```

## Цены

Стоимость хранится в `COURSE_PROGRAMS`:

```js
{
  id: "one-day",
  price: 15000
}
```

```js
{
  id: "three-day",
  price: 40000
}
```

Цены выводятся в трёх местах:

- в карточках форматов на главной;
- в карточках выбора программы на странице принтера;
- в строке метаданных на странице программы.

Чтобы изменить стоимость, поменяйте число в поле `price`. Форматирование (`15 000 ₽`) выполняется автоматически через `Intl.NumberFormat`.

## Доступ к курсу

Кнопка «Начать обучение» / «Продолжить обучение», карточки лекций и прямые ссылки на лекции защищены кодом доступа. Сейчас используется демонстрационный код:

```text
123
```

Код задаётся в `index.html`:

```js
const COURSE_ACCESS = {
  code: "123"
};
```

После верного кода открывается нужная лекция или первая непройденная лекция (при запуске через кнопку). При неверном коде показывается ошибка, диалог остаётся открытым.

Доступ запоминается отдельно для каждой пары «принтер + программа» в `sessionStorage`:

```text
picaso-access-<printerId>-<programId>
```

Это значит, что после ввода кода можно свободно переходить между лекциями выбранной программы до закрытия вкладки. Для другой программы код потребуется снова. При прямой попытке открыть лекцию без доступа сайт сначала показывает страницу программы и диалог ввода кода — содержимое лекции не отображается.

Важно: это клиентская проверка для прототипа. Она не является безопасной системой оплаты. Для реального платного доступа проверяйте оплату и права пользователя на сервере, а в `handleAccessSubmit()` замените сравнение с `COURSE_ACCESS.code` на запрос к вашему API.

## Редактирование текста

Визуально пустые блоки имеют пунктирную рамку и подсказку. Это блоки с классом `editable`. После заполнения рамка и подсказка исчезают автоматически.

Важно: повторяющиеся блоки вынесены в данные, чтобы один и тот же текст не появлялся сразу на всех карточках и лекциях.

### Одиночные блоки

Их можно заполнять прямо в разметке в `index.html`, рядом с нужным комментарием:

| Что | Комментарий-маркер |
| --- | --- |
| Описание курса в hero | `<!-- ВСТАВЬТЕ ОПИСАНИЕ КУРСА -->` |

Текст страницы «О компании» находится в функции `renderAbout()` внутри блока `.about-copy .editable`. Он уже заполнен, но его можно переписать. Ниже на этой странице автоматически строятся карточки принтеров с фотографиями.

Пишите обычный HTML: `<p>`, `<ul>`, `<strong>` и т. п. Например:

```html
<div class="editable hero-description" data-editable="hero" data-placeholder="...">
  <p>Первый абзац описания курса.</p>
  <p>Второй абзац.</p>
</div>
```

### Описания тем на главной

В функции `renderHome()` найдите массив `learnCards` и при необходимости поменяйте поле `description` у нужной темы. Сейчас тексты для всех четырёх тем уже заполнены.

```js
{ icon: "equipment", title: "Оборудование PICASO", editable: "learn-equipment", description: "<p>Короткий текст о теме.</p>" }
```

### Описания форматов и программ

В объекте `COURSE_PROGRAMS`:

- `formatDescription` — текст в карточке формата на главной;
- `description` — текст на странице программы.

Описания форматов сейчас уже заполнены. Их можно заменить своими.

Можно использовать HTML:

```js
formatDescription: "<p>Что входит в формат и как проходит день.</p>",
description: "<p>Цели программы, формат проведения и требования к участникам.</p>",
```

### Описание принтера

У каждого принтера в `SITE_CONFIG.printers` есть поле `extraDescription`:

```js
extraDescription: "<p>Особенности обучения на этой модели.</p>",
```

### Текст лекции

Материалы лекций находятся в `COURSE_PROGRAMS[].lessons[]`. У каждой лекции есть четыре поля:

```js
{
  n: 2,
  title: "Название лекции",
  description: "",  // короткое описание в списке лекций
  theory: "",       // блок «Теория»
  practice: "",     // блок «Практика / Разбор»
  checklist: []     // пункты чек-листа
}
```

1. Найдите комментарий `<!-- ВСТАВЬТЕ ТЕКСТ ТЕОРИИ -->` в `COURSE_PROGRAMS` рядом с нужной лекцией.
2. Заполните `theory` нужной лекции. Блок автоматически появится на её странице.
3. Аналогично заполняются `description` и `practice`.

`theory` и `practice` принимают HTML. Для многострочного текста удобно использовать шаблонные строки:

```js
theory: `
  <p>Первый абзац теории.</p>
  <h3>Подзаголовок</h3>
  <ul>
    <li>Пункт списка</li>
    <li>Ещё один пункт</li>
  </ul>
`,
practice: `
  <p>Практическое задание и вопросы для разбора.</p>
`,
```

Не вставляйте текст в саму функцию `renderLesson()`: это общий шаблон для всех лекций. Для конкретной лекции используйте её объект в `COURSE_PROGRAMS`.

Сейчас все принтеры используют один массив `COURSE_PROGRAMS`. Поэтому текст лекции общий для всей серии Designer, а прогресс — отдельный для каждой модели. Если нужна уникальная программа для одной модели, замените у неё `programs: COURSE_PROGRAMS` на собственный массив программ (см. раздел «Добавить программу»).

### Чек-лист обслуживания

Пункты чек-листа задаются массивом строк в поле `checklist` нужной лекции:

```js
checklist: [
  "Настройка прижима сопла",
  "Замена сопла",
  "Проверка кабель-канала"
]
```

Базовый перечень операций находится в комментарии `<!-- ДОБАВЬТЕ ПУНКТЫ. БАЗОВЫЙ ПЕРЕЧЕНЬ ОПЕРАЦИЙ ... -->` рядом с блоком чек-листа. Скопируйте нужные пункты в массив `checklist` соответствующей лекции. Список можно расширять и сокращать.

## Добавить принтер

Откройте `SITE_CONFIG.printers` и добавьте объект по образцу:

```js
{
  id: "designer-new",
  name: "Picaso Designer NEW",
  series: "Designer",
  shortDescription: "Короткое описание модели.",
  pros: [
    "Первое преимущество модели",
    "Второе преимущество",
    "Третье преимущество"
  ],
  cons: [
    "Первое ограничение",
    "Второе ограничение"
  ],
  image: "assets/printers/designer-new.webp",
  imageAlt: "Picaso Designer NEW — внешний вид",
  extraDescription: "",
  programs: COURSE_PROGRAMS
}
```

Требования к `id`:

- только латиница, цифры и дефисы;
- значение уникально;
- оно используется в hash-адресе и ключе прогресса.

Плюсы и минусы выводятся в карточке принтера на главной и в блоке «Плюсы и минусы» на странице принтера.

Каталог, страница принтера, список на странице «О компании» и счётчики обновятся автоматически. Добавьте фотографию в `assets/printers/` и укажите её в поле `image` (см. раздел «Фотографии принтеров»).

## Добавить программу

Добавьте объект в массив `COURSE_PROGRAMS`:

```js
{
  id: "five-day",
  title: "Практикум (5 дней)",
  shortTitle: "5 дней",
  level: "Практикум",
  duration: "5 дней",
  unit: "lecture", // "module" или "lecture" — влияет на подписи «3 модуля / 3 лекции»
  price: 0,
  description: "",
  formatDescription: "",
  lessons: [
    // ...
  ]
}
```

После этого программа появится у всех принтеров, которые используют `programs: COURSE_PROGRAMS`, а также в блоке форматов на главной.

Если программа нужна только одной модели, создайте отдельный массив и укажите его в поле `programs` этой модели:

```js
programs: [
  ...COURSE_PROGRAMS,
  {
    id: "private-program",
    title: "Индивидуальная программа",
    // ...
  }
]
```

`id` программы должен быть уникальным внутри принтера и использоваться в адресах вида `#/printer/<id>/program/<programId>`.

## Добавить лекцию

В нужную программу добавьте объект в `lessons`:

```js
{
  n: 4,
  title: "Название новой лекции",
  description: "",
  theory: "",
  practice: "",
  checklist: []
}
```

- `n` — целое число, уникальное внутри программы;
- маршрут лекции: `#/printer/<printerId>/program/<programId>/lesson/<n>`;
- общее количество лекций и прогресс-бар пересчитаются автоматически;
- кнопка «Начать обучение» ведёт к первой непройденной лекции после ввода кода доступа;
- карточки лекций и прямые ссылки также защищены кодом.

## Фотографии принтеров

Фотографии уже подключены и лежат в `assets/printers/`. В конфиге принтера за них отвечают два поля:

```js
image: "assets/printers/designer-xl.webp",
imageAlt: "Picaso Designer XL — внешний вид",
```

Чтобы заменить фотографию:

1. Подготовьте изображение в WebP или JPEG. Желательно квадратное, с нейтральным светлым фоном и без лишнего обвеса.
2. Положите файл в `assets/printers/` под понятным именем, например `designer-xl-new.webp`.
3. Измените `image` и `imageAlt` у нужного принтера в `SITE_CONFIG.printers`.
4. Проверьте карточку на главной, страницу принтера и мобильную версию.

Никакие шаблоны править не нужно: одна и та же фотография используется в hero, каталоге, на странице принтера и в карточках моделей на странице «О компании». Фото выводятся на светлой подложке, поэтому белый фон исходников выглядит органично.

Рекомендации:

- используйте собственные снимки или изображения, на которые у вас есть права;
- не берите фотографии и графику с picaso-3d.ru без разрешения;
- сжимайте файлы и сохраняйте единый ракурс;
- обязательно заполняйте `alt`;
- проверяйте, что путь относительный и регистр букв совпадает с именем файла — это важно для Linux и GitHub Pages.

## Типографика

Подключены три семейства Google Fonts:

| Семейство | Веса | Назначение |
| --- | --- | --- |
| Manrope | 700, 800 | заголовки H1–H3 |
| Inter | 400, 500 | основной текст и интерфейс |
| JetBrains Mono | 400 | технические подписи, цифры, цены, бейджи |

Базовый текст: `17px` / `line-height: 1.6`. Заголовки имеют трекинг `-0.02em`. Для цифр и технических подписей используются моноширинные начертания: номера лекций, прогресс, цены, статистика, «PRODUCT VIEW / 01», «ON-SITE», статусы и служебные метки.

Шрифтовые переменные находятся в начале `<style>`:

```css
--font: "Inter", ...;
--font-display: "Manrope", ...;
--mono: "JetBrains Mono", ...;
```

В `body` включён `font-synthesis: none`, чтобы браузер не подмешивал искусственные начертания и использовал только подключённые веса.

## Публикация на GitHub Pages

1. Создайте пустой репозиторий на GitHub.
2. В папке проекта выполните:

```bash
git init
git add index.html README.md .nojekyll assets/
git commit -m "Add PICASO Designer course site"
git branch -M main
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

3. Откройте репозиторий на GitHub → **Settings** → **Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**.
5. Укажите ветку **main** и папку **/ (root)**. Нажмите **Save**.
6. Через 1–2 минуты сайт будет доступен по адресу:

```text
https://<username>.github.io/<repo>/
```

Файл `.nojekyll` уже добавлен и отключает обработку Jekyll. Hash-маршруты и относительные пути работают и в корне домена, и в подпапке репозитория.

Если репозиторий уже инициализирован, начните с `git add ...`.

## Что заменить перед публикацией

- `course@example.com` — на реальный email (в хедере, футере и кнопке связи).
- `https://github.com/your-username/your-repo` — на реальный репозиторий.
- `COURSE_ACCESS.code` — на реальный код или серверную проверку оплаты.
- Название «3D-Практикум», если нужен другой бренд.
- Пустые блоки и поля контента.
- При необходимости — favicon и мета-описание в `<head>`.
- Ссылки на политику конфиденциальности и реквизиты, если они требуются для вашего проекта.

## Технические детали

- Внешняя зависимость только одна — Google Fonts (Manrope, Inter, JetBrains Mono). При недоступности сети используются системные шрифты.
- CSS и JavaScript встроены в `index.html`.
- Сторонние библиотеки, трекеры и сборочные инструменты отсутствуют.
- Иконки нарисованы инлайн-SVG; фотографии принтеров лежат в `assets/printers/`.
- Адаптивность проверена от ширины 360 px.
- Все интерактивные элементы доступны с клавиатуры; мобильное меню закрывается по Escape и клику по затемнению.
- Кнопка старта, карточки лекций и прямые ссылки на лекции защищены демонстрационным кодом; доступ хранится в `sessionStorage` отдельно для каждой программы.
- Предусмотрены состояния для неизвестных маршрутов, отсутствующего прогресса и недоступ
